# QemuM — QEMU VM Manager для Windows

Менеджер QEMU с интерфейсом WinForms, отдельной Python-службой и QMP-управлением. Поддерживает запуск VM, паузу, выключение, снимки дисков qcow2, редактирование параметров и сетевых адаптеров, Extra args со справкой, диагностику, живые логи и визуальный каталог систем.

Это репозиторий **исходников**, отделённый от рабочей установки и пользовательских данных. В нём нет конфигураций личных VM, дисков, ISO, журналов, резервных копий, секретов и готовых установщиков. Сборка и тесты не изменяют установленный менеджер.

Для обычного использования скачай EXE установщика из [Releases](https://github.com/ivan22822/QemuM/releases).
Текущая альфа: `0.1.0-alpha.2`. [Инструкция пользователя](docs/ALPHA-GUIDE.md)
объясняет установку, обновления и добровольную отправку отчёта через GitHub Issues.

## Структура

| Папка | Содержимое |
| --- | --- |
| `src/gui/` | WinForms-интерфейс, общие компоненты и manifest приложения |
| `src/backend/` | Python-служба, QMP, сеть, диски, диагностика и терминальные команды |
| `src/launcher/` | Независимый загрузчик, обновления и установщик |
| `assets/visual-assets/` | Поставляемые PNG, каталог и сведения об источниках/лицензиях |
| `tools/` | Локальная сборка, запуск проверок и аудит staged-файлов |
| `tests/unit/` | Изолированные проверки Python без личных VM |
| `tests/gui/` | Проверки WinForms и отдельная интеграция с временным QEMU |
| `examples/` | Искусственные примеры параметров, не рабочие конфигурации |
| `build/` | Результаты сборки, тестов и изолированное состояние; игнорируется Git |

## Требования

- Windows 10/11, .NET Framework 4.x с `csc.exe` для сборки GUI.
- Python 3.12+ со стандартной библиотекой для сборки и тестов. Установщик закрепляет Python 3.14.8.
- QEMU с `qemu-system-x86_64.exe`, `qemu-img.exe` и `qemu-io.exe` в `PATH` для запуска VM и интеграционных тестов.
- Git. GitHub CLI не требуется: HTTPS-аутентификация может использовать Git Credential Manager.

NuGet, pip-пакеты и скачивание зависимостей для сборки не нужны. Скрипты ничего не устанавливают в систему.

## Сборка и запуск копии для разработки

В параметрах VM доступен профиль **WHPX · совместимый**: он использует
`-accel whpx,kernel-irqchip=off -cpu host`. Выбирай его, если обычный WHPX
не запускает гостя, а команда с отключённым kernel irqchip работает.
Профиль не меняет формат диска и не отключает вложенную виртуализацию.
Перед запуском проверяются те же параметры ускорителя; VM Doctor проверяет
обычный и совместимый WHPX отдельно. Успешная проба подтверждает создание
временной VM, но не загрузку конкретной гостевой ОС. Старые VM сохраняют
выбранный профиль; «Авто» по-прежнему проверяет обычный WHPX, затем TCG.

```powershell
python tools/build.py
.\build\app\VMManager.exe
```

`build/app/` содержит EXE, служебные модули и поставляемые логотипы. Пользовательские файлы туда не копируются, а существующее содержимое не удаляется. При первом запуске библиотека пуста; VM добавляются через интерфейс. Для терминальных команд используй `build/app/vm.cmd`.

Не подставляй корень действующей установки через `--root` для проверок. Не запускай из репозитория скрипты обновления прежней установки. Их здесь нет. Установщик создаётся только по отдельному запросу.

## Сборка альфы

```powershell
python tools/release.py
python tools/test_release.py --python-archive <путь-к-python-3.14.8-embed-amd64.zip>
```

Результат — `build/release/0.1.0-alpha.2/`: EXE установщика, ZIP приложения,
`update.json` и `SHA256SUMS.txt`. Команда ничего не публикует и не устанавливает.
Тест релиза создаёт собственный экземпляр в `build/test-results/`, проверяет
контрольную сумму Python, запускает его через постоянный загрузчик и закрывает
только этот экземпляр. QEMU и личные VM для этого теста не нужны.

[Протокол обновлений](docs/UPDATE-PROTOCOL.md) должен сохраняться при замене
интерфейса или языка приложения. [Чеклист первой альфы](docs/FIRST-ALPHA-CHECKLIST.md)
содержит результаты и ещё не проверенные сценарии.

## Проверки

```powershell
python tools/test.py
python tools/test.py --gui
python tools/test.py --qemu
python tools/audit.py --staged
```

По умолчанию запускаются Python-тесты, не требующие QEMU. `--gui` добавляет проверки редакторов, селекторов, оформления и диалогов. `--qemu` включает их и проверку QMP на собственном временном qcow2 с TCG, остановленным процессором и без загрузки личной ОС. Результаты находятся в `build/test-results/`. Полная установка ОС и WHPX на другом компьютере этими проверками не подтверждаются.

## GitHub и рабочий процесс

Репозиторий: [ivan22822/QemuM](https://github.com/ivan22822/QemuM).

Каждая новая функция разрабатывается в отдельной ветке `codex/<название>`. Перед коммитом проверяются diff, тесты и состав staged-файлов. Первую отправку нужно отдельно подтвердить после просмотра состава коммита, URL и ветки. Force push запрещён; слияние в `main` выполняется только после подтверждения пользователя. Правила для агента находятся в [AGENTS.md](AGENTS.md).

Первая подготовка исходников сохраняет существующую историю `main`. Старый EXE установщика удаляется из текущего дерева проекта; его прежний коммит остаётся в истории. История не переписывается.

## Данные и графика

Конфигурации `machines/`, `appearance.json`, локальные установки Python/QEMU, пользовательские PNG, журналы и резервные копии относятся к рабочему экземпляру, а не к исходникам. `.gitignore` исключает их и распространённые форматы виртуальных дисков.

Происхождение поставляемых логотипов и сторонние лицензии: [SOURCES.md](assets/visual-assets/SOURCES.md). Они не означают лицензию на весь авторский код менеджера; общая лицензия проекта пока не выбрана.
