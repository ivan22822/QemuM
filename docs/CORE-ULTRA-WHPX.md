# Проверка WHPX на Core Ultra

Сообщено пользователем: Core Ultra 9 275HX, Windows 11 25H2, QEMU 11.0.1,
Ubuntu Desktop. TCG загружается; WHPX, включая kernel-irqchip=off, завершается
с `Unexpected VP exit code 4`. Перед этим есть предупреждения APX/MPX.
На таком процессоре разработчиком не воспроизведено.

## Уточнение: WHPX с qemu64

Пользователь позднее подтвердил успешный запуск через PowerShell с WHPX,
CPU `qemu64,+ssse3,+sse4.1,+sse4.2,+popcnt`, машиной `pc`, видеокартой `std`
и SDL без OpenGL. Маскирование APX/MPX, в том числе вместе с отключением
kernel-irqchip, не помогло. Нельзя объявлять WHPX целиком неработающим на этом CPU.

В сборке 4 добавлен профиль `WHPX · qemu64 + SSE4/POPCNT`:

```
-accel whpx -cpu qemu64,+ssse3,+sse4.1,+sse4.2,+popcnt
```

Выбрать профиль для выключенной VM и сохранить параметры. Он меняет только
ускоритель и CPU. Машина QemuM остаётся `q35`, выбор видеокарты и Extra args
сохраняются; SDL без OpenGL уже используется по умолчанию при отсутствии
переопределения display в Extra args. Это перенос CPU из рабочей команды,
а не полное воспроизведение всей команды. Успешный запуск именно через QemuM
на компьютере друга ещё требуется подтвердить. Старые VM автоматически
не переводятся на этот профиль.

## Отдельный экспериментальный профиль

`WHPX · без APX/MPX (экспериментальный)` передаёт:

```
-accel whpx -cpu host,mpx=off,apxf=off
```

Он выбирается вручную в параметрах VM. Существующие VM и пользовательские
настройки не переписываются. Профиль не отключает IRQ chip: это отдельное
сравнение с обычным WHPX, а не повтор уже неудачного совместимого профиля.
После ошибки реального запуска нет автоматического повторного запуска диска.

В установленной версии с редактором профилей можно создать свой профиль:
ускоритель `whpx`, опции ускорителя пустые, CPU `host,mpx=off,apxf=off`.
Не добавлять второй `-cpu` или `-accel` через Extra args.

Перед сменой профиля штатно выключить гостевую ОС. Проверять ту же VM,
меняя только профиль. Сохранить результат загрузки и полный лог QEMU.
Если VP exit 4 остаётся, использовать подтверждённый пользователем TCG и
продолжить исследование; не объявлять проблему исправленной.

## Границы проверки

APX и MPX используют пересекающееся состояние XSAVE. QEMU уже обрабатывает
их конфликт в коде CPU, поэтому явное отключение не гарантирует решения.
VP exit 4 означает невосстановимое исключение виртуального CPU; его причина
не устанавливается по одному номеру. Diskless-проверка Doctor подтверждает
создание приостановленной VM и QMP, но не загрузку Ubuntu.

Источники:

- [Обработка CPU features в QEMU](https://gitlab.com/qemu-project/qemu/-/blob/master/target/i386/cpu.c)
- [Причины выхода виртуального процессора WHPX](https://learn.microsoft.com/en-us/virtualization/api/hypervisor-platform/funcs/whvexitcontextdatatypes)

Для подтверждения обхода на 275HX нужны успешная загрузка, работа гостя
после входа и повторный запуск на выключенном госте. Пока это эксперимент,
а не заявленная поддержка всей серии Core Ultra.
