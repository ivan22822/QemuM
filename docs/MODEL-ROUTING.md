# Подбор модели по задаче

Предпочтение пользователя от 30 октября 2026. Это рабочая эвристика проекта,
не рейтинг по измерениям и не гарантия цены/качества. Текущий запрос пользователя
важнее этих defaults. Предлагать только доступные в текущем клиенте варианты.

## Первый ответ

Вместе с моделью рекомендовать место работы по CHAT-ROUTING.md, сохраняя общий
лимит двух коротких строк. При необходимости распределение этапов включить
в ту же краткую рекомендацию, не разворачивать отдельный план ради маршрутизации.

Перед инструментами дать одну строку: «Рекомендую: 6.1 Sol Medium — [краткая причина]».
Для составной задачи добавить максимум одну строку распределения этапов, например:
«Архитектура — Sol High; реализация и тесты — Sol Medium; FAQ — Terra Medium».
Это предварительная оценка по запросу и уже известному контексту, без запуска
тестов, чтения всего проекта, отдельного агента или отдельного API-запроса.
Не повторять рекомендацию на каждую мелкую реплику в рамках той же задачи.

| Задача | Начальная рекомендация |
| --- | --- |
| Мелкая правка кода, обычный GUI, тесты по готовому контракту | 6.1 Sol Medium |
| Сеть, QMP, ownership, конкурентность, данные/обновлятор, сложная диагностика | 6.1 Sol High |
| FAQ, формулировки, разбор скриншотов, визуальная концепция, работа через UI | 6.1 Terra Medium |
| Архитектура с высокой неопределённостью, особо сложная нерешённая причина | 6 Astra High |

Medium/High — эвристика глубины, не утверждение об одинаковой стоимости режимов
разных моделей. Большое число файлов само по себе не повод для Astra/Max/Ultra.
Если уже выбрана подходящая модель, не предлагать переключение ради предпочтения
другого семейства или короткого этапа, когда затраты переключения не оправданы.
Для текущей настройки правил достаточно Sol Medium.

## Изменение оценки в процессе

Повышать рекомендацию при новой сложности: скрытая гонка, риск повреждения данных,
неясный контракт, противоречивые результаты или две содержательно разные попытки
устранить причину без прогресса. Один провал теста или недоступный socket/файл —
не повод автоматически менять модель. Сначала отличить среду от сложности задачи.

Сообщить один раз до трудного этапа: «Рекомендую переключить на Sol High:
[причина]. Следующий этап — [название]». Для Astra назвать конкретную причину,
почему текущего подхода недостаточно. Не запускать дополнительные проверки
исключительно ради выбора модели. При переходе к существенно более простому
длинному этапу можно предложить снижение режима один раз, без частых переключений.

Модель переключает пользователь в интерфейсе. Агент не меняет account settings,
не утверждает, что переключился, и не пытается запускать другой экземпляр модели.
Если пользователь хочет переключиться, сохранить краткую точку продолжения;
не тратить дорогой этап на текущей модели, выдавая его за работу рекомендованной.
Без явного требования ждать сам совет не блокирует уже разрешённую работу.

## Экономия

В начале — не более двух коротких строк. Далее уведомлять только при изменении
оценки, без рутинных статусов. Не проверять каталог моделей и цены при каждой
задаче; уточнять только при изменении доступности, названий, явном запросе цен
или устаревании справочных сведений. Обязательные инструкции skills сохраняются.

Официальная справка, сверена 30 октября 2026:
[Models](https://learn.chatgpt.com/docs/models). Она описывает роли семейств
и ручной выбор модели/глубины. Таблица режимов выше — локальная рекомендация.
