# Снимки и независимые копии · Альфа 4

Снимок диска возвращает его содержимое к выбранному моменту. Это не отдельная
резервная копия: потеря исходного образа может уничтожить и его снимки.
Сохранение параметров VM отдельно от диска не сохраняет файлы гостевой ОС.

## Создание и восстановление

1. Выбери VM → «Снимки дисков» → «Создать снимок».
2. Введи название и описание. «Сохранить параметры VM» — добровольный выбор.
   Пароли и ключи в аргументах не сохраняются: при их обнаружении действие
   отклоняется, чтобы не получить скрыто неполную конфигурацию.
3. Для обычной точки выбери «Снимок дисков». Проверь план: все записываемые
   диски входят в одну группу; ISO и read-only устройства исключаются.
4. Подтверди действие. Окно показывает реальные этапы; проценты появляются
   только при измеримом копировании/чтении. ID операции нужен для диагностики.
5. Для отката выключи гостевую ОС, выбери точку → «Загрузить снимок». Укажи,
   восстанавливать ли также сохранённые параметры и запускать ли VM после
   завершения. Запуск является отдельным действием после подтверждённого отката.
6. Служба сначала создаёт страховочную точку, проверяет рабочие копии и только
   затем заменяет образы. Старые образы сохраняются; потребуется дополнительное
   место. Не удаляй служебные папки во время работы.

Пример для лабораторной VM: выключи гостя, создай «До обновления пакетов»,
запусти VM и обнови пакеты. Если результат не подходит, штатно выключи гостя,
восстанови эту точку без автозапуска, проверь параметры и запусти VM отдельно.
Перед рискованным экспериментом дополнительно сохрани независимый ZIP.

## Типы и пределы поддержки

| Тип | Условия | Что сохраняется |
|---|---|---|
| Внутренний снимок | Незашифрованные qcow2 без backing; все writable диски принадлежат одной VM | Диски; онлайн по умолчанию crash-consistent |
| Офлайн-снимок | VM выключена; полное копирование и проверка перед заменой | Диски и по выбору параметры |
| Внешняя цепочка | Выключенная VM, один writable диск; приватная копия qcow2/VDI/raw базы | Неизменяемые точки и новые qcow2-ветви |
| Полное состояние | Только проверенная сборка QEMU, TCG, max/qemu64/qemu32, разрешённые устройства, VM на паузе | Диски, RAM, CPU и устройства |
| Независимая копия | VM выключена, новый ZIP на локальном диске | Развёрнутые самостоятельные qcow2/raw; RAM исключена |

Исходный VDI при создании внешней цепочки копируется, не превращается в backing
пользовательского файла и не изменяет атрибуты оригинала. Зарегистрированные
зависимости проверяются перед запуском. Зависимые слои не удаляются как отдельные
файлы. Commit/rebase/merge предоставляют только план; выполнение отключено.

RAM-точки требуют той же сборки QEMU и совместимых параметров; версия интерфейса
менеджера в этот контракт не входит. WHPX RAM отключён: реальные пробы QEMU
11.1.1 выявили отсутствие необходимого сохранения состояния. Непроверенные
устройства, host CPU, passthrough, Guest Agent и дополнительные каналы в RAM-режиме
отклоняются. RAM может содержать пароли и документы; не прикладывай такие образы
к Issues. При неопределённом RAM-откате нужна исходная приостановленная VM для
компенсации; если процесс уже потерян, автоматический запуск запрещён и необходима
отдельная ручная проверка сохранённых дисков/страховочной точки.

Подготовка файловых систем через Guest Agent требует явно настроенного отдельного
канала и установленного гостевого агента. Менеджер не устанавливает агент в гостя.
Независимый защитник ограничивает freeze и пытается выполнить thaw даже после
падения основного процесса. Если thaw не подтверждён, запуск/продолжение блокируется.
Протокол и аварийный защитник проверены с тестовым агентом; реальные гостевые
ext4/NTFS и приложения с базами данных пока не аттестованы этим набором тестов.

Собственные временные тесты покрывают 1/2/3 диска; измерение чтения каталога —
15 групп на трёх маленьких дисках, оконный список — 200 записей. Это проверенные
сценарии, не обещание скорости для больших дисков. Терабайтные образы и внезапное
физическое отключение питания не проверялись. После ввода изменений рост
внутренних снимков расходует место; виртуальный размер не равен занятому размеру.

## Независимый ZIP

«Ещё…» → «Независимая копия…». Выбери конкретный снимок или текущее состояние,
новый ZIP, формат дисков и необходимость полного сравнения/SHA-256. Структурная
проверка и независимость образов проверяются всегда. Для копии параметров выбранной
точки они должны быть сохранены в ней заранее. Параметры могут содержать личные
пути; не публикуй архив без проверки.

Экспорт работает с приватными клонами и разворачивает backing-зависимости.
До проверки ZIP находится под временным именем. Существующий файл не заменяется.
Служба резервирует консервативный бюджет для клонов, развёрнутых образов,
проверочного результата и ZIP; сжатие и sparse-файлы не считаются гарантией.
FAT/FAT32, UNC и сменные носители не поддерживаются.

Для восстановления распакуй ZIP в новую папку, прочти `manifest.json` и создай
новую VM с `disk-0.qcow2`/`disk-0.raw` и дополнительными дисками из manifest.
При необходимости перенеси допустимые параметры вручную. Не подменяй исходную VM.
Если выбран raw, для запуска используй дополнительный `-drive ...,format=raw`
или отдельно конвертируй копию в qcow2; основной селектор QemuM принимает qcow2/VDI.

## Отмена, история и восстановление после ошибки

«Отменить операцию» доступна только до публикации и в измеримых этапах копирования,
хеширования и упаковки. Во время команды qemu-img запрос ожидает следующего
безопасного этапа. После начала замены образов отмена недоступна. Закрытие окна
или менеджера не должно прерывать запись. После аварийного завершения процесса
повторное открытие каталога обнаруживает журнал; операция не повторяется вслепую.

При ошибке открой «Ещё…» → «История операций» / «Незавершённые операции…».
Служба сверяет файловые ID и известные версии каталога, подтверждает публикацию
либо возвращает прежние образы. Неизвестные подменённые файлы не перезаписываются.
Если результат не подтверждён, VM остаётся заблокированной. Неполная группа не
выдаётся за пригодную точку восстановления. Повторная сверка не создаёт новую точку.

Каталог и журналы находятся в пользовательских данных:
`data/snapshot-state/<ключ VM>/catalog.json` и `operations/<ID>.json`.
Рабочие копии и прежние образы — в `.qemum-stage-<ID>-<номер>` рядом с дисками;
они не удаляются автоматически. Журналы ограничены 512 шагами, новые операции —
2000 записями на VM; существующие аварийные журналы никогда не вытесняются.
При достижении лимита требуется осознанное архивирование завершённой истории.

В «Помощь / отчёт» можно добровольно отметить «Журнал операций снимков».
В отчёт попадут ID, этапы и статусы, последние 50 завершённых операций и
незавершённые в пределах 2 МБ. Полные планы, RAM и образы не включаются. Известные
пути скрываются при включённом маскировании. Проверь ZIP и прикрепи его к Issue
вместе с ID операции, состоянием VM, временем и описанием ожидаемого результата.

## Расписание

«Ещё…» → «Расписание и хранение…». По умолчанию выключено. Работает только
при открытом менеджере, без скрытой службы. После сна выполняется максимум один
пропущенный запуск. Очистка — только после выключения VM, только для пригодных
автоматических точек. Ручные, защищённые, неполные, RAM и аварийные точки не
удаляются. Внешние зависимости не очищаются по правилам внутренних снимков.
