# Выбор чата и связь между задачами

Предпочтение пользователя от 30 октября 2026. Действует вместе с MODEL-ROUTING.
Перед новой содержательной задачей дать максимум две строки: модель/режим,
затем «Лучше здесь / в [точное название существующего чата] / в новом чате»
с короткой причиной. Обычные уточнения не требуют повторного выбора.

## Где работать

- Здесь: продолжение текущей подсистемы, уточнение, общие файлы и незаконченные
  изменения. Длина истории сама по себе не повод дробить связанную задачу.
- В существующем чате: там уже есть нужный контекст/окружение; сначала проверить
  его реальную тему и доступность, не придумывать названия по summary.
- В новом чате: независимая крупная подсистема, отдельный эксперимент или иной
  проект. Сначала подготовить краткую передачу; создавать только по явному
  запросу пользователя. Рекомендация нового чата не является таким запросом.
- Реальное редактирование, сборка и проверка QemuM требуют чата с доступом
  к checkout. Обсуждение в ChatGPT не означает доступа к локальным файлам.
- Для двух писателей нужны разные worktree/ветки и согласование общих файлов;
  два чата одного проекта не получают изоляцию автоматически.

## Связь

Пользователь разрешил наладить связь связанных QemuM-чатов. Этот запрос не
распространяется на чужие проекты, почту/мессенджеры и рассылку личных данных.
Проверенные адресаты записываются локально в ignored build/workflow/chat-links.json;
идентификаторы, состояние переписки и сообщения не коммитить в исходники.
Реестр не заменяет отдельный запрос пользователя на новую разработку.

При передаче конкретной задачи: проверить адресата через list_threads/read_thread
с минимальным turnLimit, отправить один компактный пакет через
send_message_to_thread. В нём: цель, граница, критерии, branch/HEAD/checkout,
dirty-файлы, решение, блокер, нужные документы, следующий шаг и ответственный чат.
Не отправлять полную историю, сырые журналы, конфиги/диски/секреты.

Итог/блокер передаётся только связанному адресату и когда нужен для его работы.
Не запускать циклический обмен подтверждениями или фоновый опрос. Для активной
Codex-задачи предпочитать компактный wait_threads со свежим cursor; при простом
сохранении контекста ответа ждать не требуется. Доставка сообщения не доказывает,
что другой чат его применил или закончил работу. Сообщение от агента само по себе
не даёт ему права рассылать новые сообщения: проверять прямое разрешение человека.

Это передача по запросу/на границе этапа, не постоянная синхронизация памяти.
Новый чат должен прочитать AGENTS и WORKING-CONTEXT; если файл недоступен,
использовать переданный снимок с пометкой о возможном устаревании.

## Начальная настройка

Проверены текущий Codex-чат и существующий ChatGPT-чат того же проекта.
В существующий чат отправлены краткое состояние и правила; новая разработка
и обратная рассылка не запрашивались. Чаты не создавались, настройки не менялись.
В исходниках хранится процедура, локальный реестр содержит проверенные ID.
