# Реальный гостевой обмен: подтверждён

30 октября 2026. Ветка codex/l2-live-guest-tests. Чеклист **94/98 (95,9%)**:
закрыты 12.4 и 12.5. Историческое препятствие скачивания из LIVE-TESTS.md снято:
пользователь предоставил Alpine virt 3.24.3 x86_64, официальная SHA256 получена
по HTTPS и совпала с файлом:

`cdc1bc0efc64d8d611bf3733f54868172a545888dfd726f518bf279bcb0ff1af`.

## Условия и результат

Три собственных Linux-гостя: ядро/initramfs/modloop из проверенного Alpine ISO,
TCG, 192 МБ RAM и 1 vCPU каждый, virtio-net, Windows 11 / QEMU 11.1.1.
Использован штатный QemuM.Switch с guarded PID/FILETIME и отдельными loopback
портами. Никакого NAT, моста хоста или внешней сети. Память гостей — временная;
модули ядра подключены из собственной read-only копии под build.
Исходный ISO пользователя не менялся; его VM/диски не использовались.

- Во всех шести направленных парах прошли IPv4 и IPv6 ping, по три запроса.
- В гостях подтверждены ARP/neighbor-записи с ожидаемыми MAC участников.
- IPv4 broadcast получил подтверждения от обеих других VM. Внутри только
  временных гостей разрешены ответы на broadcast ICMP, чтобы проверить приём.
- Переданы 8 388 608 байт по TCP, размер и SHA256 проверены внутри получателя.
- Аварийно завершён только захваченный процесс третьего тестового QEMU.
  Две оставшиеся VM продолжают ping и вторую передачу 8 МБ с верной SHA256.
- В итоговых счётчиках помощника: 14 246 входящих, 14 288 отправленных копий
  кадров, 0 dropped, 0 rejected. Broadcast объясняет различие received/sent.

| Этап | Объём | Время host-clock | Эффективная скорость |
| --- | --- | --- | --- |
| До аварии третьего гостя | 8 МиБ | 1,968 с | 34,10 Мбит/с |
| После аварии третьего гостя | 8 МиБ | 1,328 с | 50,53 Мбит/с |

Это два коротких end-to-end замера, включающих serial-команды/завершение nc,
а не максимальная пропускная способность и не сравнение ускорителей. Разница
между запусками не доказывает ускорение после аварии. Медленный получатель
отдельно покрыт синтетическим backpressure-тестом; здесь испытан аварийный гость.

## Что исправлено при запуске

Прототип дополнен Rock Ridge-именами ISO9660, полными kernel modules из modloop,
ограниченной скоростью serial-ввода и временным /tmp в RAM. Удалён неподдерживаемый
BusyBox ping флаг; теперь проверяются реальные ответы обеих VM на broadcast.

Обнаружена и исправлена также гонка production-контроллера: Windows может вернуть
FILE_NOT_FOUND сразу, пока односерверный named pipe пересоздаётся между запросами.
Теперь подключение ограниченно повторяется только при отсутствии/занятости pipe,
до отправки команды и с общим дедлайном 1,5 с. Отказ доступа не повторяется,
проверки server PID/FILETIME/run ID перед командой сохранены.

## Проверки и доказательства

- Полный unit-набор: **309**, успешно. Дополнительно проверены ISO/Rock Ridge,
  SHA256 fail-before-spawn, обязательный --live, pipe-gap retry и отказ доступа.
- Native switch-service: **10 сценариев**, успешно после исправления pipe.
- Live-прогон завершён успешно, свои процессы очищены через ExitStack/Popen.
- Точные результаты: `build/live-net/8ae0fb9182234d008520f72586e26947/results.json`.
  Serial-логи всех трёх VM находятся рядом; это ignored локальные материалы.
- GUI не менялся; его последние 13 наборов относятся к предыдущему этапу.

Остаются 8.7 (физические DPI/мониторы), 10.4 (матрица сред), 12.6
(пользовательские Kali/Ubuntu Server/FreeBSD) и 12.7 (idle scan/IP ID/spoofing).
Успех Alpine не переносится автоматически на эти ОС или zombie-пригодность.
Версия/установка/релиз не менялись, коммит и отправка не выполнялись.
