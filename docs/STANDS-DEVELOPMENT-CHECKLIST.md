# Стенды QemuM — подробный чеклист разработки

Дата: 23 октября 2026. Статус: план, реализация не начата.
Этот документ не разрешает запуск VM, изменение установки или публикацию.

## 0. Зафиксированные требования

- [x] Записать: пользователь самостоятельно создаёт стенд, выбирает VM, связи и порядок запуска.
- [x] Записать: тумблер переключает обычные VM и стенды с вложенными участниками.
- [x] Зафиксировать компоновку со скриншота: список СЛЕВА, карточка и параметры СПРАВА в обоих режимах.
- [x] Зафиксировать регулируемую ширину левого списка для длинных названий.
- [x] Сохранить стилистику «Полярная ночь», общие кнопки, поля, меню и прокрутку.
- [x] Разделить текущий этап документации и последующую интеграцию. Новое превью не создавать.

## Правила выполнения и учёта

Отмечать пункт только после реализации и проверки; форма без backend не считается
готовой функцией. Для каждого раздела записывать файлы, тесты, результат и
ограничения. Процент реализации считать по незавершённым при создании пунктам
разделов 1–30; фиксация требований не увеличивает процент готовности функции.
Текущий статус: базовая реализация разделов 1–10; см. STANDS-FOUNDATION.md. Итоговый отчёт отделяет локальные исходники,
установленную программу и опубликованную сборку. Не выполнять реализацию по
одному факту наличия этого чеклиста.

## 11. Редактор соединений

- [ ] Выбирать две VM и их сетевые адаптеры.
- [ ] Отображать связи понятными подписями и портами участников.
- [ ] Проверять петли на один адаптер, дубликаты и занятые конечные точки.

- [ ] Чётко указать: соединение не настраивает IP/DHCP внутри гостя автоматически.
- [ ] Добавить удаление/редактирование связи с подтверждённым планом изменений.

## 12. Сетевой backend

- [ ] Выбрать поддерживаемый backend для связи двух/нескольких VM.
- [ ] Для socket-связей обеспечить запуск listen до connect.
- [ ] Проверять доступность слушателя, а не подменять это фиксированной паузой.
- [ ] Выделять уникальные порты и сетевые ID без конфликтов с QMP/QGA/hostfwd.
- [ ] Сохранять MAC, предотвращать дубликаты в общем сегменте.
- [ ] Привязывать служебные listener к localhost по умолчанию.
- [ ] Генерировать argv без shell, с корректными кавычками и запятыми.
- [ ] Не переписывать постоянную сеть одиночной VM при запуске стенда.

## 13. Совместимость сетей

- [ ] Выявлять конфликт существующих Extra args и управляемых адаптеров.
- [ ] Сохранять текущие NAT, hostfwd, MAC и standalone-настройки.
- [ ] Не подключать уже работающую VM к иной сети молча.
- [ ] Показывать эффективные настройки до запуска.
- [ ] Проверить два одновременно работающих стенда и одинаковые имена сетей.
- [ ] Предусмотреть безопасное возвращение к обычному запуску VM.

## 14. Очерёдность запуска

- [ ] Реализовать перемещение вверх/вниз и доступное редактирование порядка.
- [ ] Сохранять порядок независимо от сортировки списка слева.
- [ ] Поддержать ограниченные задержки перед отдельными этапами.
- [ ] Проверять совместимость пользовательского порядка с listen/connect.
- [ ] Не переставлять машины скрытно: объяснять необходимую зависимость.
- [ ] Проверять циклические зависимости и отсутствие участников.

## 15. Готовность и тайм-ауты

- [ ] Отличать «процесс создан», «QMP готов» и «гостевая ОС готова».
- [ ] Не показывать задержку в секундах как гарантию загрузки ОС.
- [ ] Реализовать ограниченные тайм-ауты каждого условия.
- [ ] При необходимости добавить опциональную TCP-проверку или QGA.
- [ ] Явно обозначить требования и отсутствие Guest Agent.
- [ ] Не хранить пароли гостя и не выполнять произвольные команды готовности.

## 16. Предварительная проверка

- [ ] Проверять существование VM, образов, зависимостей и исполняемых файлов.
- [ ] Проверять профили WHPX/TCG и поддерживаемость параметров.
- [ ] Выявлять конфликт владения записываемыми дисками и pending-операции снимков.
- [ ] Оценивать запросы RAM/vCPU с учётом уже работающих VM.
- [ ] Показывать предупреждение о ресурсах без обещаний точной производительности.
- [ ] Выводить итоговый план: кто уже работает, кто стартует, какие сети используются.

## 17. Исполнение запуска

- [ ] Ввести UUID операции и неизменяемый план с revision участников.
- [ ] Использовать существующий проверенный механизм запуска одиночной VM.
- [ ] Проверять PID, время создания процесса и идентичность QMP.
- [ ] Запускать последовательно согласно зависимостям и готовности.
- [ ] Не создавать второй процесс при повторном клике/повторном RPC.
- [ ] Обрабатывать завершение VM между проверкой и следующим этапом.
- [ ] Поддержать частично работающий стенд и явное продолжение недостающих этапов.

## 18. Отмена и ошибки

- [ ] Отмена прекращает будущие старты и имеет явно описанную судьбу запущенных VM.
- [ ] Никогда автоматически не завершать VM, работавшие до операции.
- [ ] Для запущенных текущей операцией применять только утверждённую политику отката.
- [ ] Отличать отмену, ошибку VM, тайм-аут, конфликт и неопределённый результат.
- [ ] Показывать конкретного участника и безопасное следующее действие.
- [ ] Повторная попытка не выполняет уже подтверждённые этапы вслепую.

## 19. Остановка стенда

- [ ] Спроектировать отдельное штатное выключение стенда.
- [ ] По умолчанию предложить обратный порядок зависимостей.
- [ ] Отдельно подтверждать включение ранее работавших участников в остановку.
- [ ] Ожидать подтверждённого завершения с ограниченным тайм-аутом.
- [ ] Принудительное завершение выделить в самостоятельное явное действие.
- [ ] Не удалять диски, конфигурации, снимки и дампы при остановке.

## 20. Runtime-состояния

- [ ] Описать состояния VM: выключена, запускается, работает, остановка, ошибка, неизвестно.
- [ ] Описать состояния стенда: выключен, запускается, работает частично, работает, ошибка.
- [ ] Отображать реальный этап и текущего участника.
- [ ] Не показывать фиктивный процент готовности загрузки ОС.
- [ ] Не блокировать GUI ожиданием QMP/сети/процесса.
- [ ] При смене выбранного стенда сохранять доступ к выполняющейся операции.

## 21. Журнал и восстановление

- [ ] Сохранять намерение до запуска и подтверждение после каждого этапа.
- [ ] После перезапуска менеджера сопоставлять записи с фактическими процессами.
- [ ] Не присваивать стенду чужой процесс по одному PID или имени.
- [ ] При неизвестном состоянии блокировать опасное повторение и предлагать сверку.
- [ ] Ограничить объём истории, сохранять незавершённые операции.
- [ ] Не выполнять автоматический старт стенда при открытии менеджера.

- [ ] Не использовать отображаемое имя как путь каталога или сетевой идентификатор.

- [ ] Проверить разные ускорители, смесь уже работающих и новых VM.
- [ ] Проверить отмену, аварийное завершение менеджера и повторное открытие.

## 30. Definition of Done

- [ ] Обычный режим VM сохраняет прежнее поведение.
- [ ] Пользователь сам создаёт стенд и видит его папкой слева.
- [ ] Справа работают параметры выбранного стенда и вложенной VM.
- [ ] Длинные названия читаются при изменении ширины списка.
- [ ] Состав, связи и порядок сохраняются и реально используются backend.
