# Непрерывное владение образами: протокол и проверенные примитивы

Этап 1–10, 22.10.2026. `ImageLease` в vm_snapshot_lease.py использует Win32 CreateFileW с GENERIC_READ|DELETE и FILE_SHARE_READ. Дескриптор оригинала живёт всё время многосоставной операции. Другие открытия для записи или удаления получают отказ Windows, даже если QEMU данной сборки сам не блокирует образ. Уже открытый несовместимым процессом образ невозможно зарезервировать; группа целиком отклоняется до подготовки.

Порядок: mutex домена → VM → отсортированные файловые ID → резервирование всех исходных файлов. После получения всех дескрипторов повторно проверяются идентичность, конфигурация и каталог. Копирование идёт ReadFile из удерживаемого дескриптора в новый приватный файл, по 4 МиБ, с реальным счётчиком и отменой. qemu-img работает исключительно с приватными копиями; исходный образ он открыть для записи не может. Отказ на втором диске освобождает ранее полученные дескрипторы без изменения файлов.

Протокол будущей публикации офлайн-группы:

1. Журнал намерения содержит ID операции, пары оригинал/копия/страховочный файл, исходные файловые ID, хеш конфигурации/каталога и подтверждённые шаги.
2. Все рабочие копии проверены qemu-img info/check, снимок найден ровно один раз на каждом диске. Пока это не так, оригиналы не переименовываются.
3. Получить ImageLease на все готовые копии. Проверить их ID против подтверждённых результатов. Исходные дескрипторы остаются открытыми.
4. Записать намерение каждого перемещения. Переименовать оригинал в страховочный путь через SetFileInformationByHandle, затем копию — на исходное имя, тоже через её открытый дескриптор. Windows-блокировка следует за самим файлом и сохраняется после переименования. Нельзя закрывать дескриптор ради удобства os.replace.
5. Любая неожиданно занятая цель вызывает отказ, а не перезапись. Если между перемещениями сторонняя программа создаст файл на освободившемся имени, он не удаляется автоматически. Все свои оригиналы и журнал сохраняются; обычный запуск заблокирован до сверки.
6. После публикации всех файлов обновить каталог одним CAS: заменить файловые ID всех существующих групп согласно явной карте замены и добавить новую группу. Самопроизвольная перепривязка при чтении по-прежнему запрещена.
7. Записать completed и только затем освободить дескрипторы. Страховочные образы не удалять в аварийных ветках. При ошибке перемещения компенсировать только по известным дескрипторам/ID; неизвестный файл не заменять.
8. При аварии worker Windows освобождает его handles. Незавершённый журнал блокирует QemuM, следующий запуск сначала сверяет фактические позиции файлов. Это не обещание атомарности файловой системы на несколько дисков и не защита от аппаратной потери питания.

Публикация, компенсация и восстановление подключены в OfflineTransaction для пользовательских внутренних офлайн-снимков/откатов/удаления. Все оригиналы и публикуемые копии остаются под native-дескрипторами до завершения записи каталога. Создание включено только после интеграционных проверок. Старая guarded helper-функция остаётся для совместимости/регрессионных тестов, пользовательские внутренние откаты GUI и терминала переведены на новый механизм. Отдельные внешние цепочки имеют свою модель readonly-базы и графа; её ограничения не следует смешивать с ImageLease-публикацией внутренних qcow2.

Подтверждено тестами: запрет записи/удаления другим handle; копирование через собственный handle; отмена без изменения исходника; сохранение запрета записи после перемещений оригинала и копии; отказ от перезаписи занятой цели; освобождение первой резервации при конфликте второй. Отдельный тест реального qemu-img подтверждает: исходник под ImageLease недоступен для мутации, приватная копия доступна, байты исходника сохранены.

Источники Win32: [CreateFileW — sharing](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info).
